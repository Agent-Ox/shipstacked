## Caveats

- **Velocity Score formula** (per audit): commits last 90d (max 40) + Build Feed posts last 90d (max 30) + profile completeness (max 30). It rewards activity + completeness, NOT outcome-narrated projects. That's why Ryan Grant scores 100 with 0 projects (heavy on commits + posts + completeness), and why Andreas/Emanuel/Nneka/Thomas all score 0 despite being verified (no recent Build Feed posts and/or no GitHub).
- **github_data freshness**: per the github_data table's `last_synced` column, the data is from the date each builder first connected — most are stale by a month or more. The `commits_90d` count is a snapshot of "90 days before sync", not 90 days before today. None of the GitHub data has been refreshed since each user's initial onboarding sync. This is a known gap; doesn't affect the ranking but bear in mind when claiming current activity.
- **No `pg_meta` access**: this audit infers schema from sample rows. The `velocity_score` recompute logic was read from `src/app/api/velocity/calculate/route.ts` during the earlier site audit — it's not re-derived here.
- **Test/seed profile detection** (Jenny Peterson, John Chambers): based on the GitHub username pointing at the platform's own `Agent-Ox` org, identical contribution graphs, and dummy-style bios. High confidence but not 100% — Thomas should confirm before any cleanup action.
